# Документация модуля комментариев

## 1. Введение

Модуль комментариев является частью системы управления учебными проектами «Student Project Manager». Он предоставляет REST API и веб-интерфейс для управления комментариями к задачам.

**Функциональность:**
- Добавление комментариев к задачам (с поддержкой вложенных ответов).
- Редактирование и удаление комментариев (мягкое удаление).
- Проверка статуса задачи (запрет комментирования закрытых задач).
- Уведомление автора задачи при добавлении комментария (заглушка).
- Ограничение времени редактирования (10 минут после создания).

## 2. Пользовательская документация

### 2.1 Быстрый старт

1. **Запуск сервера**
   Из папки проекта выполнить: `python app.py`
   Сервер будет доступен по адресу `http://127.0.0.1:5000`.

2. **Веб-интерфейс**
   Открыть в браузере `http://127.0.0.1:5000/comments`.
   - Введите ID задачи и нажмите «Загрузить» – отобразятся комментарии.
   - Добавляйте комментарии, отвечайте, редактируйте и удаляйте через кнопки.

3. **API (для разработчиков)**
   Доступно по адресу `http://127.0.0.1:5000/api/comments/`.
   Примеры запросов см. в разделе 3.3.

### 2.2 Основные сценарии

| Действие | Через веб-интерфейс | Через API (curl) |
|----------|---------------------|------------------|
| Просмотр комментариев задачи | Ввести ID задачи → «Загрузить» | `GET /api/comments/?task_id=1` |
| Добавление комментария | Написать текст → «Отправить» | `POST /api/comments/` с JSON |
| Редактирование | Нажать ✏️, изменить текст | `PUT /api/comments/{id}` |
| Удаление | Нажать 🗑️, подтвердить | `DELETE /api/comments/{id}` |
| Ответ на комментарий | Нажать 💬 Ответить, написать текст | Передать `parent_comment_id` в POST |

## 3. Техническая документация

### 3.1 Архитектура

Модуль построен по слоёной архитектуре:

| Слой | Файл | Назначение |
|------|------|------------|
| Представление (API) | `api.py` | REST-эндпоинты, сериализация, кэширование |
| Бизнес-логика | `services.py` | Проверка статуса задачи, уведомления, временные ограничения |
| Доступ к данным (CRUD) | `crud.py` | Операции с БД, валидация |
| Модели данных | `models.py` | ORM-классы User, Task, Comment |
| Конфигурация | `config.py` | Константы (длина комментария, лимиты) |
| Расширения | `extensions.py` | Инициализация db, migrate, cache |

### 3.2 Схема базы данных (ER-диаграмма)
┌─────────────┐ ┌────────────────────────────┐
│ users │ │ comments │
├─────────────┤ ├────────────────────────────┤
│ id (PK) │◄──────│ author_id (FK) │
│ email │ │ id (PK) │
│ name │ │ content │
│ password_hash│ │ created_at │
│ created_at │ │ updated_at │
└─────────────┘ │ is_deleted │
│ task_id (FK) ──────────────►┌─────────────┐
┌─────────────┐ │ parent_comment_id (FK) ────►│ tasks │
│ tasks │ └────────────────────────────┘├─────────────┤
├─────────────┤ │ id (PK) │
│ id (PK) │ │ title │
│ title │ │ description │
│ description │ │ author_id │
│ author_id │ │ status │
│ status │ │ deadline │
│ deadline │ │ created_at │
│ created_at │ └─────────────┘
└─────────────┘

text

Связи:
- `users (1) → comments (M)` – один пользователь может написать много комментариев.
- `tasks (1) → comments (M)` – одна задача может иметь много комментариев.
- `comments (1) → comments (M)` – один комментарий может иметь много ответов (self-referential).

### 3.3 API Эндпоинты

| Метод | URL | Описание | Тело запроса | Ответ (успех) | Коды ошибок |
|-------|-----|----------|--------------|---------------|-------------|
| POST | `/api/comments/` | Добавить комментарий | `{"content":"text", "task_id":1, "parent_comment_id":null}` | 201, JSON комментария | 400, 403, 500 |
| GET | `/api/comments/` | Список комментариев задачи (пагинация) | Параметры: `task_id`, `page`, `limit` | 200, `{"data":[...], "pagination":{...}}` | 400, 404, 500 |
| GET | `/api/comments/{id}` | Получить один комментарий | – | 200, JSON комментария | 404, 500 |
| PUT | `/api/comments/{id}` | Редактировать комментарий | `{"content":"new text"}` | 200, JSON комментария | 400, 403, 404, 500 |
| DELETE | `/api/comments/{id}` | Удалить (мягкое) | – | 200, `{"message":"Deleted"}` | 403, 404, 500 |

**Примечания:**
- Все запросы требуют JWT-аутентификации (в текущей версии – заглушка `get_current_user()` возвращает 1).
- Кэширование GET-эндпоинтов – 30 секунд (Flask-Caching).

### 3.4 Инструкция по развёртыванию

**Локальный запуск (разработка):**

1. Клонировать репозиторий:
   `git clone https://github.com/denis5cabinet/student-project-manager.git`
   `cd student-project-manager`

2. Создать и активировать виртуальное окружение:
   `python -m venv venv`
   `source venv/bin/activate` (Linux/macOS)
   `venv\Scripts\activate` (Windows)

3. Установить зависимости:
   `pip install -r requirements.txt`

4. Создать таблицы БД и заполнить тестовыми данными:
   `python -c "from app import app; from extensions import db; from models import User, Task, Comment; with app.app_context(): db.create_all()"`
   `python seed.py`

5. Запустить сервер:
   `python app.py`

**Запуск через Docker** – будет реализован в работе 4.5.
